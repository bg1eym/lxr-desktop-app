## 1. Three small firmware issues: 0-length tracks after SD format, read of address 0, CodecInit() signature

> Hi, and thanks for open-sourcing the firmware!
>
> I compiled this firmware (1.7, `a43cd4f`) for a desktop computer and for WebAssembly, replacing only the hardware layer, to build an emulator. Running the firmware's own code on another CPU surfaced three small issues. I can't check their effect on the hardware myself, so the "on the device" parts below come from reading the code.
>
> ### 1. Formatting a card saves project 0 with every track length 0
>
> `sd_formatRoutine()` ([main.c#L108-L185](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/main.c#L108-L185)) runs before `soundengine_init()` ([main.c#L471](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/main.c#L471)), so `seq_init()` has not cleared the patterns yet: `seq_patternSet` is still all zero when `preset_saveProject(0)` ([main.c#L172](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/main.c#L172)) writes it. After the reboot, project 0 is loaded with track length 0 ([presetManager.c#L1850](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Preset/presetManager.c#L1850)) and the sequencer computes `(step+1) % length` with `length == 0` ([sequencer.c#L946](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/Sequencer/sequencer.c#L946), [#L1111](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/Sequencer/sequencer.c#L1111), [#L1175](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/Sequencer/sequencer.c#L1175)).
>
> On the Cortex-M7 an integer division by zero gives 0 when `SCB->CCR.DIV_0_TRP` is clear (the firmware doesn't set it), so nothing crashes, but `x % 0 == x` and the step index isn't wrapped. On x86 and WebAssembly it traps, which is how I found it.
>
> Possible fix: call `seq_init()` before `preset_saveProject(0)` in `sd_formatRoutine()`, or otherwise give the patterns their default length of 16 as `seq_clearTrack()` does ([sequencer.c#L2556](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/Sequencer/sequencer.c#L2556)). The emulator calls `seq_init()` there, and the formatted card then plays normally.
>
> ### 2. `modNode_setOriginalValueChanged()` reads through a NULL pointer
>
> [modulationNode.c#L49](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/DSPAudio/modulationNode.c#L49): when a modulation node's destination has no `ptr` (destination 0), `*((uint8_t*)p->ptr)` reads address 0. On the F7 that is ITCM, so it reads a byte of code and nothing breaks, and the value is never written back because every writer checks `p->ptr`. `modNode_setDestination()` already guards the same case ("PATROT we want to avoid reading from invalid memory", [modulationNode.c#L134](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/DSPAudio/modulationNode.c#L134)); adding the same `if(!p->ptr) return;` makes it safe on other targets too.
>
> ### 3. `CodecInit()` is declared and defined without parameters but called with one
>
> [AudioCodecManager.h#L23](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Inc/Soundengine/AudioCodecManager.h#L23) and [AudioCodecManager.c#L24](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/AudioCodecManager.c#L24) say `int CodecInit()`, [Soundengine.c#L46](https://github.com/erica-synths/lxr-desktop-app/blob/a43cd4f/Core/Src/Soundengine/Soundengine.c#L46) calls `CodecInit(SYNTH_FS)`. Harmless with GCC on ARM, but it is an error from C23 on (where `()` means no parameters), and WebAssembly can't make that call at all. Either drop the argument or declare `int CodecInit(uint32_t audioFreq)`.
>
> I'm happy to open a PR for any of these.

## 2. Unofficial browser emulator built from this firmware: interested, and is the name OK?

> Hi Erica Synths team,
>
> Thank you for releasing the LXR-02 firmware as open source. I used it to build an unofficial emulator: the firmware's own sources (1.7, `a43cd4f`) compiled to WebAssembly and running in an AudioWorklet, with a virtual front panel.
>
> - Live: https://bg1eym.github.io/lxr-desktop-app/
> - Source (GPL-3.0): https://github.com/bg1eym/lxr-desktop-app/tree/emu (`emu/`, `web/`, design notes in `docs/EMULATOR_PLAN.md`)
>
> Only the hardware layer is replaced (HAL and CMSIS intrinsics, codec/DMA, the display, the SD card driver, shift registers, ADC, encoder pins). The sound engine, sequencer, menus and preset code are compiled unchanged, apart from one `#ifdef` for the read of address 0 that I reported in a separate issue together with two other small findings.
>
> What works so far: the whole panel (display, LEDs, pots, data encoder, faders, all buttons), the sequencer, and a virtual SD card that is kept in the browser. The emulator runs at the device's exact clock ratios (I2S 44140.625 Hz, TIM14 3999.7 Hz), float-to-int casts saturate like VCVT, and the native and WebAssembly builds produce bit-identical output. The goal is to let owners prepare kits and patterns on a computer and move them to the hardware on the SD card, and later to sync parameters over Web MIDI.
>
> To follow NOTICE.md, the start-up screen shows "Unofficial Emu / based on fw 1.7", the page says it is not affiliated with or approved by Erica Synths and links to the source, and the virtual panel is a generic layout with no Erica Synths artwork or logos.
>
> Two questions:
>
> 1. Would you be interested in having this in this repository (for example as `emu/` and `web/` directories with a CI job that keeps them building), or would you rather it stays a separate project?
> 2. Naming: it is currently called "LXR-02 Emu (unofficial)". Is that acceptable to you, or would you prefer a name that doesn't use your trademarks, with "for the Erica Synths LXR-02" only as a compatibility statement? I'm happy to rename it.
>
> Thanks!
